# Ask Better
## 18 prompts for research and product decisions

By Essy Udeme · Tools & Templates

Use these with an AI assistant or as questions for your own review. Replace each bracketed field with your notes or draft. Supply only material you have permission to share. Ask for missing information to be named, and check every quotation and source reference yourself.

## Research

### 01. Name the research question
Using [brief], draft three research questions. For each, name the decision it will inform and the evidence needed to answer it. State what the brief does not tell you. Do not invent people, findings or sources.

### 02. Plan the conversations
Using [research question] and [description of participants], write six open questions about their recent behaviour. Ask about an actual task before asking about preferences. For each question, explain what the answer will help us decide. Flag leading questions and replace them.

### 03. Separate the observation
Read [notes with source IDs]. Create a table with observation, source ID, interpretation and another possible explanation. Keep direct quotations unchanged. Mark any interpretation that the notes do not support. Do not treat a repeated quote as several people.

### 04. Check the source coverage
Using [question] and [source list with dates], identify which parts of the question each source answers. List the people, dates or situations missing from the source list. Finish with three next checks that would reduce those gaps. Do not supply citations outside the material provided.

### 05. Inspect the alternatives
Using [competitor notes with links and dates], compare the task, intended user, stated price and observed features. Separate what the source says from your interpretation. Mark missing fields as unknown. Suggest what to verify before using the comparison in a decision.

### 06. Write a research brief
Using [findings and source IDs], write a brief with question, method, observations, limits and decisions the work supports. Attach source IDs to every observation. Include contradictory evidence. End with what we still need to check, without claiming the work represents everyone.

## Decisions

### 07. Compare the options
Using [options], [evidence] and [constraints], compare each option's intended user, task, effort and first test. Use written reasons, not invented scores. Identify the unknown most likely to change our choice. Suggest a next check before recommending an option.

### 08. Identify the assumptions
Review [plan]. List each assumption about the person, behaviour, demand, delivery or cost. For each, state what the plan relies on, what evidence we have and how to check it. Keep assumptions separate from verified facts.

### 09. Check the scope
Review [first-version plan]. List what it includes, what it leaves out, and the assumption each part is intended to test. Flag features that do not help answer the chosen question. Propose a smaller version and explain what evidence we would lose by removing each part.

### 10. Set the boundaries
Using [brief], [time available] and [dependencies], draft a scope note with included work, excluded work, delivery requirements and unresolved decisions. Name the person who needs to answer each unresolved question. Do not invent dates or approvals.

### 11. Design the first test
Using [assumption] and [available participants or data], propose a test. Specify the thing someone will try, the observation to record, the time required and the decision each response will support. Identify limits and risks of misreading the response.

### 12. Record the choice
Using [comparison] and [chosen option], write a decision note: what we chose, the evidence we used, alternatives we paused, what we deliberately left out and what would make us reconsider. Name a review date from [schedule]. If no date is supplied, leave that field blank.

## Critique

### 13. Review the first visit
Using [screens or page text] and [intended task], describe what a new visitor sees first and what action they can take. Identify unexplained terms, missing context and competing actions. Suggest three changes, each connected to a specific observation in the supplied material.

### 14. Follow the product flow
Using [flow description or screenshots], trace the task from entry to completion. List each action, expected response, failure state and recovery route. Mark any step the material does not show. Do not claim to have clicked or tested something you have only read.

### 15. Review the brief
Read [brief]. Check that it names a person, task, problem, source, decision, first version, constraint and first test. Quote the passage covering each item or mark it missing. Suggest the fewest edits needed to make the brief usable.

### 16. Check the story
Read [draft] as an unfamiliar reader. Identify any claim that needs a source and any sentence that needs a clearer subject. Suggest edits that preserve the author's meaning. Do not add statistics, client names, quotes or personal experiences.

### 17. Interpret the test
Using [test plan] and [observations], separate what happened from explanations of why it happened. Identify which assumptions the test supports, contradicts or leaves unanswered. Keep the sample and limits visible. Propose the next decision without generalising beyond the observations.

### 18. Prepare the handoff
Using [work description], [known issues] and [recipient's task], draft a handoff note. Include what is ready, how to use it, unresolved items, file locations and where to send feedback. Keep unprovided names, links and dates as blank fields. Do not describe unfinished work as finished.

## Before using an answer

Read it against the original material. Verify sources, calculations and quotations. Remove claims you cannot support. Keep the decision and its reasons in your own project notes.
